00 / THE STARTING POINT

A little setup. Then write.

This repository is an agent skill plus a local scanner. Pick one agent below; you do not need all three.

A / GET THE FILES

Open the repository root

Clone or download the GitHub repository and open a terminal in its folder. You should see SKILL.md, references/, and scripts/.

B / CHECK YOUR TOOLS

An agent, plus optional Node.js

Use an authenticated CLI with access to a model. Install Node.js 18+ for this repo's scanner and evals. No npm install is needed for the repo itself; CLI requirements are separate.

Clone the repository
git clone https://github.com/adityaarakeri/humanize-content.git
cd humanize-content

No Git? Download the ZIP, extract it, and open a terminal in the extracted folder.

Updates installation commands throughout this guide.

Using WSL? Choose Bash and install the CLI and skill inside the same WSL environment. Its home folder is separate from your Windows home.

  1. Install the CLI and sign in

    Follow the Codex installation guide, then open a new terminal. Launch Codex and complete its sign-in flow. Verify the executable is available:

    Terminal

  2. Put the skill where Codex can find it

    Run from the root of this downloaded repository. This installs a personal copy for use across your projects. Keep all three parts together.

    PowerShell

cp SKILL.md "$skill/"

    Expected: SKILL.md, references/, and scripts/ directly inside ~/.agents/skills/humanize-content. Re-run after updating this repository; review any local customizations first.

  3. Open the folder containing your draft

    Save your text as draft.md in a writing project. Replace the example path with that folder, then launch the agent there.

    PowerShell
    Set-Location 'C:\path\to\your-writing-project'
codex
    Bash / zsh
    cd "/path/to/your-writing-project"
codex

  4. Load the skill and make your first pass

    Start a fresh session after copying the skill. Open /skills and look for humanize-content. Then send the prompt below. Enter this in the agent chat, not your shell.

    The explicit skill mention

    ✓ Expect a rewritten draft, requests for missing facts when needed, and a brief change summary. Ask for text only if you do not want the notes.

04 / EVERYDAY USE

Give the draft a direction.

State the mode, the audience, and where the text will go. Add two or three samples of your own writing when you want the result to sound like you.

DEFAULT

Rewrite

A full pass with clean copy, missing-input requests, and a short explanation of changes.

AUDIT ONLY

Detect

Quoted findings with pattern IDs and severity. Your draft stays untouched.

SMALL EDITS

Patch

Minimal edits in the file, followed by a diff-style summary. Review the changes before publishing.

PASTE INTO ANY AGENT CHAT AFTER LOADING THE SKILL

Detect prompt
Use the humanize-content skill in Detect mode on draft.md.
Report pattern IDs, severities, and quoted excerpts. Do not rewrite or edit the file.
Patch prompt
Use the humanize-content skill in Patch mode on draft.md.
Make the smallest necessary edits in place. Preserve facts, code, and URLs.
Show a brief diff-style summary.

Name the platform

Say where the text will go: X post, X reply, LinkedIn post, LinkedIn reply, Slack reply, or Messages reply (SMS, iMessage, WhatsApp). For replies, paste the message you are answering. The skill keeps replies short and will not invent a stance, story, or plan. Example: “Use the humanize-content skill to rewrite this as a Slack reply.”

Make the voice yours

Add: “Use voice-sample-1.md and voice-sample-2.md as voice references. This is for an email to existing customers. Keep it direct and warm.” Create those files first. Replace every [FILL: ...] with a verified fact before publishing.

05 / THE QUALITY CHECK

Read it. Scan it. Test it.

Save the result before scanning. Run these commands from this repository root, replacing the quoted path with your actual draft path.

PowerShell
node scripts/check.js "C:\path\to\your-writing-project\draft.md"
Bash / zsh
node scripts/check.js "/path/to/your-writing-project/draft.md"
Scanner exit codes
CodeMeaningNext action
0No P0 findingsReview any P1/P2 findings and read the draft.
1P0 findings foundInspect the flagged passages and fix applicable issues.
2Usage or file errorCheck the command and input path.

The scanner flags patterns. A clean scan does not prove human authorship or factual accuracy.

Maintaining the skill? Run the offline checks.

Offline checks
npm run ci

npm run ci runs syntax checks, tests, eval fixture checks, and a documentation scan. It makes no model calls.

Run a live Codex writing eval

Requires an authenticated Codex CLI and model access. Replace YOUR_MODEL with an available model ID. This makes model calls and uses your account's quota or billing.

Live eval
node evals/codex.js --model YOUR_MODEL --trials 3

Three trials per case. Reports, prompts, responses, usage, and logs go into a unique directory under evals/outputs/, which Git ignores. Exit 0 means all quality checks pass; 1 means a quality failure; 2 means a CLI or argument failure. These are focused regression checks, not a general writing-quality score.

Evaluate Claude Code or OpenCode manually

List cases, then print a prompt:

Prepare a case
node evals/run.js --list
node evals/run.js --prompt law1-vague-metrics

Send the printed prompt in an agent session with this skill installed. Save the final response as evals/outputs/manual/law1-vague-metrics.md. Create the output folder first. Repeat for other case IDs, then grade:

Grade saved responses
node evals/run.js evals/outputs/manual

Cases without saved responses are skipped; a partial run is not full coverage. The automated live runner is currently Codex-only.

06 / WHEN SOMETHING GETS STUCK

Get back to the draft.

The agent cannot find the skill

Check the exact folder and uppercase filename SKILL.md. The file must sit directly inside humanize-content/, not another nested copy. Restart the agent. Ensure the CLI and skill use the same OS environment and home directory. OpenCode skill permissions or organization policies can also restrict discovery.

The skill loads, but references or the scanner fail

Copy both references/ and scripts/ beside SKILL.md. Ask the agent to resolve supporting files relative to the installed skill directory. Resolve your draft path relative to your writing project. Check node --version if the scanner cannot start.

The wrong version seems to be running

Look for duplicate personal and project installations. OpenCode can also see Codex and Claude skill folders. Keep one intended copy per discovery path and update its supporting files along with SKILL.md. Restart the session after cleanup.

I only want the skill in one project

Copy the same three parts into your target project's .agents/skills/humanize-content/ for Codex, .claude/skills/humanize-content/ for Claude Code, or .opencode/skills/humanize-content/ for OpenCode. Launch the agent from that project. Use this instead of a personal installation when sharing the skill with a team.

PowerShell blocks npm or the eval loses arguments

If your execution policy blocks an npm PowerShell shim, use npm.cmd run ci. Run the live eval directly with node evals/codex.js --model YOUR_MODEL --trials 3. Prefer file inputs over piping text through older PowerShell, which can change Unicode encoding.

The output has a [FILL: ...] placeholder

The draft needs a fact the model was not given. Supply the real measurement or detail, or remove the unsupported claim. Check that no placeholders remain before sharing the final text.
